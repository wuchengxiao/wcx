# 大模型推理生成文本回复的基本逻辑

## 一句话概括

大语言模型通常不是一次性写出整段回复，而是根据当前已有的上下文，反复预测“下一个 token”，把预测结果追加到上下文中，再继续预测，直到遇到停止条件。

## 推理流程

1. **准备输入**：将系统提示词、对话历史和用户问题按模型要求拼成提示文本（prompt）。
2. **分词**：Tokenizer 把文本转换成 token ID 序列。一个 token 可能是一个字、词的一部分、标点或空白，并不一定对应一个汉字。
3. **模型计算**：把 token ID 输入 Transformer。模型结合上下文计算每个可能的下一个 token 的分数（logits）。
4. **选择下一个 token**：将 logits 转成概率，再按解码策略选择一个 token。例如取概率最高者，或按温度、top-k、top-p 等规则采样。
5. **追加并循环**：把新 token 追加到序列末尾，作为下一轮输入的一部分，再预测下一个 token。
6. **判断停止**：生成到结束 token、达到最大生成长度，或触发其他停止条件时结束。
7. **解码输出**：把生成的 token ID 转回文本，作为模型回复返回给用户。

## 简化伪代码

```text
tokens = tokenize(prompt)

循环，直到满足停止条件：
    logits = model(tokens)
    next_token = select_next_token(logits, decoding_config)
    tokens.append(next_token)

    如果 next_token 是结束 token：
        停止

reply_tokens = tokens 中新生成的部分
reply = detokenize(reply_tokens)
返回 reply
```

实际实现中通常只把新生成的部分作为回复返回，而不会把提示词本身再次输出。

## 下一个 token 怎么选

- **贪心解码**：每一步选概率最高的 token。结果稳定，但可能比较刻板。
- **温度（temperature）**：调整概率分布的尖锐程度。温度较低时更偏向高概率 token；较高时选择更多样，但随机性也更强。
- **Top-k**：只在概率最高的 k 个候选 token 中采样。
- **Top-p（核采样）**：从累计概率达到 p 的最小候选集合中采样。

这些设置影响生成的随机性和多样性，不会改变模型已经学到的参数。

## 为什么要逐 token 生成

自回归语言模型学习的是根据前文预测后续 token 的概率：

```text
P(token₁, token₂, ..., tokenₙ)
= P(token₁) × P(token₂ | token₁) × ... × P(tokenₙ | token₁, ..., tokenₙ₋₁)
```

因此生成时需要把前面已经生成的内容纳入上下文，再预测下一步。

## KV Cache 的作用

如果每生成一个 token 都从头计算整个上下文，会重复进行大量计算。推理时通常使用 **KV Cache** 保存前面 token 在注意力层中计算出的 Key 和 Value。后续步骤只需计算新 token 对应的部分，从而加快生成；它不改变生成逻辑或最终答案的定义。

## 生成与训练的区别

- **训练**：使用大量文本调整模型参数，让模型学会预测下一个 token。
- **推理**：固定模型参数，根据给定提示词执行上述逐 token 预测与选择流程。
