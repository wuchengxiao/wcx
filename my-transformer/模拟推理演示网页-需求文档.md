# 模拟大模型推理演示网页——需求文档

## 1. 文档目的

定义一个使用 HTML、CSS、JavaScript 实现的浏览器端演示网页，用直观方式展示简化的 Tokenization、共现统计 Embedding、Self-Attention 和逐 token 预测生成，并提供提示词配置、用户提问及回复生成。

> 本产品不接入任何真实模型或模型 API，也不进行真实模型训练或大模型推理。它使用共现统计和固定规则生成演示用 Embedding，以简化的自注意力计算形成上下文向量，再与 N-gram 统计共同用于逐 token 预测。页面必须明确标注这些是教学用简化算法，不等同于 Transformer 的完整实现、大模型推理或真实预训练。

## 2. 产品目标

- 用户可以通过上传和维护多个 Markdown（`.md`）文件建立本地演示语料。
- 语料发生变化后，系统自动更新 token、N-gram 统计和演示用 Embedding；三维空间以低维方式可视化 token Embedding 的语义关联，位置更接近表示共现特征更相近。推理时由 Embedding 经 QKV 计算 Self-Attention 权重，并逐 token 选择候选；三维显示坐标本身不直接参与计算。
- 用户可以配置角色设定或对话系统提示词。
- 用户输入问题后，页面依据上下文逐步选择下一个 token，并显示最终生成的回复。
- 语料统计处理过程保持简洁：只显示“预训练中...”和“预训练完成。”，不展示逐文件处理步骤、日志或中间结果。

**版本范围**：当前版本实现浏览器端 N-gram 统计、共现统计 Embedding、简化 Self-Attention 生成模拟与三维关系可视化；不调用任何真实模型。基于知识库进行检索、问答引用等功能延期至下一版本，不纳入本版本范围。

## 3. 使用对象与运行环境

- **使用对象**：希望了解 Tokenization、Embedding、自注意力、N-gram 统计、逐 token 生成和语料关联可视化概念的演示者或学习者。
- **运行环境**：现代桌面或移动浏览器；前端使用 HTML、CSS、JavaScript。
- **数据范围**：默认在浏览器本地运行。语料、token 统计、提示词及演示状态应优先保存在本地，不上传至服务器。

## 4. 页面模块

页面包含以下五个主要模块。布局可采用单页纵向分区或左右栏布局，并适配窄屏。

### 4.1 语料统计（模拟预训练）

**功能需求**

- 支持一次选择并导入多个 `.md` 文件。
- 展示已导入语料文件的名称及基本状态，并允许添加、替换、删除文件。
- 新增、替换或删除文件后，自动重新统计当前语料，不要求用户另行点击“训练”按钮。
- 语料为空时展示清晰的空状态提示。
- 对非 Markdown 文件、无法读取的文件和空文件进行基本校验；不得将无法处理的文件静默当作成功导入。
- 刷新页面后，已导入的语料文件和处理结果应尽量从浏览器本地恢复。若受浏览器存储限制而无法保存，应提示用户重新导入。

**更新状态展示**

- 开始处理时只显示：**预训练中...**
- 处理成功且结果已保存到浏览器后，只显示：**预训练完成。**；不得再显示其他完成提示或处理结果摘要。
- 不显示逐文件处理过程、分类步骤、坐标计算过程、进度日志或调试信息。
- 更新期间应避免并发处理造成旧结果覆盖新结果；若用户连续修改，应以最后一次提交的语料内容为准。
- 预训练结果（token 统计、N-gram 计数、分类、来源位置、坐标、边界及相关关联数据）应自动保存到浏览器本地存储。保存成功后才显示“预训练完成。”；页面刷新或重新打开后应优先恢复最近一次成功保存的结果。保存失败时不得显示成功状态，应提供简短错误提示并保留先前已保存的有效结果。

**模拟学习规则**

1. 使用固定、可复现的轻量 tokenizer 处理当前所有 Markdown 文件：英文按单词拆分，中文按单个汉字拆分，数字序列作为一个 token，标点作为独立 token；Markdown 标记不作为正文 token。段落和句子边界必须保留，具体规则在界面帮助中说明。不得声称该 tokenizer 等同于大模型使用的 tokenizer。
2. 对每个 token 标注类型（汉字、英文单词、数字或标点等），并关联来源文件和文本位置（例如文件名、段落序号、token 序号）。同一 token 在不同位置出现时保留多个位置引用；类型标注只用于查看，不参与 N-gram 候选评分。
3. **演示用 Embedding**：为每个不同语料 token 构造独立于三维显示坐标的向量 `e(token)`，维度固定为 16 维。统计同一独立序列内左右各 2 个 token 的窗口共现，计算 `PPMI(w,c)=max(log((count(w,c)×total)/(count(w)×count(c))),0)`，按上下文 token 构成每个 token 的 PPMI 向量，再用按语料版本固定种子生成的随机投影映射到 16 维并归一化。`BOS`、`EOS` 等边界 token 使用固定种子生成的专用向量。该向量是可复现的共现统计表示，不是通过神经网络训练得到的真实大模型 Embedding。
4. 为每个 token 的 16 维 Embedding 生成确定性的 3D 显示投影 `(x, y, z)`，供查看 token 之间的近似语义位置；显示点更接近表示其共现特征更相似。可在投影位置上按后续规则做有限的布局调整以处理共现聚集和位置冲突，因此 3D 显示位置是 Embedding 关系的近似可视化，不是用于 QKV 计算的原始向量。相同语料及算法版本应尽量维持稳定布局。
5. **坐标边界与空间容量**：系统自动为 x、y、z 轴计算初始最小值和最大值，坐标范围应围绕原点并保持适度紧凑，禁止使用无界随机数或产生差距过大的随机坐标。设需要分配坐标的不同 token 总数为 N，系统必须保证初始三维范围内至少有 `30 × N` 个满足最小间距要求的可用坐标位置；计算范围时应同时考虑最小点间距和空间容量。若语料增加导致容量不足，系统自动扩大坐标边界并重新布局或补充分配，不得将 token 挤到重叠位置。所有初始生成及后续坐标更新均须限制在当前边界内；系统可在界面中展示自动计算出的各轴范围。
6. 将同一语料序列内相邻出现的两个 token 按实际先后顺序计为有方向的共现（出现 `A` 后接 `B` 时只增加 `A→B` 计数；语料中出现 `B` 后接 `A` 时才增加 `B→A` 计数）；句子、段落或文件边界处不得错误地把两侧 token 拼成相邻序列。
7. **禁止 token 坐标重叠**：任意两个不同 token 的三维坐标不得相同；默认要求任意两点的三维欧氏距离至少为 1 个坐标单位。该最小间距应作为可配置参数。为便于判断空位和抢占，坐标空间按最小间距划分为有限的合法位置槽；每个槽最多容纳一个 token。
8. 每次记录到一对 token 共现时，让两者在三个坐标轴上同时向对方靠近。每个坐标轴单次移动量最多为 1 个坐标单位；以更新前的坐标计算双方新坐标，并且不允许相互越过。某轴上的间距小于或等于 2 时可向中点靠近，但必须遵守最小间距约束。
9. **允许级联抢占位置**：若 token 移动到的合法位置槽已被占用，移动的 token 可以抢占该槽，并触发原占用 token 自动搬移。被搬移的 token 优先选择周围最近的空闲合法位置槽；若其周围搜索范围内没有空位，则从周围被占用的位置中随机选择一个槽进行抢占，并继续搬移该槽原占用 token，依此级联，直到找到空位并完成搬移链。搬移位置应优先保持在当前坐标边界内；只有无可用位置时才按空间容量规则扩展边界。随机抢占应使用可复现的伪随机规则，使相同语料和相同处理顺序可得到稳定结果。
10. 级联搬移必须维护位置槽占用状态，避免两个 token 同时占用同一位置；同一搬移链中不得重复搬移已访问的 token。搜索范围应逐步扩大，并受最大搬移步数保护；若仍无法完成，应安全终止本次坐标更新并保留更新前的有效布局，不得留下重叠或部分损坏的结果。
11. 初始化随机坐标时，应检测与已有 token 的距离；若位置已占用或小于最小间距，则重新选择空闲合法位置槽。每次坐标更新及级联搬移后也应进行碰撞检测和修正，确保任意两个不同 token 始终满足最小间距。
12. 多次共现重复执行靠近规则，因此共现越多，相关 token 在空间中通常越接近。三维显示位置是用于演示关联的可视化，不代表真实语义向量或模型内部参数。
13. 对同一批语料重新处理时，需清晰定义共现统计口径，避免每次重算都把历史靠近效果重复累积。建议以当前语料从保存的初始／稳定坐标重新计算本轮结果，或保存本轮共现计数并据此确定坐标；不得因重复点击或页面重载无意改变坐标。

**N-gram 统计与持久化**

- 语料处理时，先按句末标点、段落边界和文件边界切分为互不重叠的独立序列，再对每条序列统计 1-gram、2-gram 和 3-gram 计数；每条序列开头添加起始标记、末尾记录结束标记，不得跨序列拼接或重复统计。
- 根据上下文末尾最多两个 token 查找后续 token 的计数，计算候选分数：`count(context, candidate) / sum(count(context, all candidates))`。该值仅是当前 N-gram 计数归一化结果，不是真实模型概率。
- 若完整上下文没有候选，按 3-gram → 2-gram → 1-gram 顺序回退；若仍没有候选，使用明确标注的兜底行为（默认停止并提示没有匹配的语料模式），不得按三维距离猜测下一个 token。
- 保存 tokenizer 规则版本、N-gram 计数及来源位置，保证刷新后可恢复；语料变更时从当前完整语料重新计算，避免重复累计旧计数。
- N-gram 计数用于限定候选集合并提供统计频率；候选排名还可结合自注意力输出向量与候选 Embedding 的相似度，具体融合规则见推理过程。
- 16 维 Embedding 向量是 QKV 和候选相似度计算的输入；三维坐标是其语义关系的低维可视化，不直接代替 Embedding 向量或进入注意力／候选评分公式。

**Embedding 与位置编码**

- Embedding 向量从 token 的局部共现统计确定性生成；语料改变时重新计算，算法版本和随机投影种子随快照保存。
- 推理时为上下文中每个 token 的 Embedding 加上固定规则生成的正弦位置编码，得到带位置信息的向量。它用于演示“token 内容表示 + 序列位置表示”，不是模型训练得到的位置参数。
- 系统提示词、角色设定或用户输入中出现语料未见过的 token 时，统一使用固定且可复现的 `<UNK>` Embedding 表示；它仍可进入 Self-Attention，但若 N-gram 无可用候选，按无匹配规则停止生成，不得临时随机造向量或候选。
- 向量维度、向量值、位置编码和来源统计可通过“查看计算细节”区域检查；默认页面不显示预训练内部步骤，仅展示规定的状态文案。

**三维可视化需求**

- 预训练模块提供 **“展示空间位置”** 按钮；预训练结果成功保存后启用该按钮，用户点击后以弹窗方式打开三维空间视图。
- 弹窗使用三维散点视图呈现文字单元及其 `(x, y, z)` 坐标，支持鼠标拖动进行 360 度旋转、滚轮或控件放大缩小，并提供恢复默认视角和关闭操作。
- 弹窗应适配桌面和移动屏幕；打开时聚焦弹窗，关闭时返回触发按钮，并支持 Esc 关闭。
- 点旁显示文字标签；点过密时可减少重叠标签，并允许用户选中点查看完整文字、分类和来源位置。
- 投影到屏幕上的文字标签应进行避让，避免标签相互遮挡；必要时可隐藏部分标签或使用引导线，且不得通过移动数据点来掩盖标签重叠。
- 可用线条或距离表达文字单元之间的共现关联；图例需说明其含义。
- 提供坐标数值展示，便于确认三维位置；预训练语料为空时不显示伪造数据。
- 用户每次打开弹窗时，应展示最近一次成功保存的完整结果；预训练更新期间不可把半成品结果写入已保存数据或在弹窗中冒充最新结果。

### 4.2 微调／提示词配置

**功能需求**

- 提供角色设定输入框，允许用户描述助手身份、语气、回答风格和约束。
- 提供系统提示词输入框，允许用户定义对话开始前提供给模拟系统的指令。
- 角色设定和系统提示词可以分别填写；两者会作为生成上下文输入，但由于采用局部 N-gram 统计，不保证回复会遵循其语义指令。
- 提供清空或恢复默认内容的操作。
- 配置内容在页面刷新后可从浏览器本地恢复。

**术语说明**

本模块属于提示词配置，不会修改模型参数，也不是真实的模型微调。界面可将用户要求的模块标题显示为“微调／提示词配置”，并明确这一点。

### 4.3 用户输入

- 提供多行文本输入框和“发送”按钮。
- 支持 Enter 发送、Shift+Enter 换行；移动端发送按钮必须可用。
- 输入为空时不启动推理，并给出简短提示。
- 推理正在进行时，避免重复提交；可提供取消或重置当前演示的操作。
- 用户与系统的每轮提问和回复都应按时间顺序显示在对话区，作为可查看的完整会话记录。
- 不得自动删除或隐藏较早的用户输入、系统回复或对话上下文；即使续写达到长度／上下文限制，也只停止本轮续写，不影响已显示的会话记录。
- 提供“清空会话”按钮，用户点击一次即可清除当前全部提问和回复记录，并重置当前会话上下文；清空操作不得影响已保存的预训练结果或提示词配置。
- 对话记录较长时可在对话区域内滚动查看，但不得以滚动、分页或折叠为由丢弃记录。

### 4.4 推理过程

- 用户提交输入后，系统按固定顺序组合系统提示词、角色设定、已显示的对话历史和当前用户输入，使用与预训练阶段相同的 tokenizer 转为 token 序列。完整对话始终保留并显示；每轮生成可设置最大输入上下文长度，超限时在算法输入中优先保留系统提示词、角色设定、当前用户输入及最近的完整对话轮次，并从最早的对话轮次开始省略。省略仅影响本轮算法输入，不删除界面上的历史记录。
- 对上下文中每个 token 取 Embedding 并加上固定正弦位置编码，生成输入向量序列 `X`。位置维度为偶数 `d` 时，使用 `PE(pos,2i)=sin(pos/10000^(2i/d))`、`PE(pos,2i+1)=cos(pos/10000^(2i/d))`；索引按上下文中的 token 位置计算。使用固定、按算法版本确定的矩阵 `WQ`、`WK`、`WV` 计算 `Q=XWQ`、`K=XWK`、`V=XWV`；这些矩阵不训练、不在线更新。
- 演示一层、一个注意力头的因果 Self-Attention。位置 i 只允许关注当前位置及之前的位置；计算 `α(i,j)=softmax((Qi·Kj)/sqrt(d))`，并以 `zi=Σ α(i,j)Vj` 得到上下文向量。下一 token 的查询表示取最后一个上下文位置的 `z`。界面展示最后位置对历史 token 的注意力权重，并可查看权重随生成 token 追加而更新。
- 以当前上下文末尾最多两个 token 查找 N-gram 候选；无候选时依次回退，按 3-gram → 2-gram → 1-gram 顺序缩短。上下文总长度超限时，优先保留系统提示词、角色设定和当前用户输入；若这些内容本身超过限制，则保留系统提示词及角色设定，并从当前用户输入开头截短，且在界面中标明本轮输入受到长度限制。
- 对候选 token `c`，计算 N-gram 频率 `p_ngram(c|context)`，以及最后位置 Self-Attention 输出 `z` 与候选 Embedding `e(c)` 的余弦相似度。融合模拟分数定义为 `score(c)=λ·log(p_ngram(c|context)+ε)+(1−λ)·cosine(z,e(c))`；`λ` 和 `ε` 为可配置／固定并显示的算法参数。该分数不是训练所得 logit 或真实概率。
- 默认对候选融合分数做 softmax 后按权重采样；支持贪心模式。温度 `T>0` 时使用 `softmax(score/T)`，`T=0` 时选分数最高者；Top-k（如启用）先保留融合分数最高的 k 个候选再采样。相同分数按 token 字符串稳定排序，采样使用可复现的伪随机种子。
- 将所选 token 追加至本轮生成序列和后续查询上下文，然后重复候选查找及选择；允许 token 在同一回复中重复出现，不因 token 已出现过而排除。
- 如果逐级回退后仍无候选，按预设规则停止本轮生成并提示“没有匹配的语料模式”；不得改用三维距离选择 token。Self-Attention 负责构造当前上下文表示，不凭空创造候选 token。
- 若语料为空或未生成可用的 N-gram 统计，应禁用生成操作或提示用户先导入语料，不得生成伪造的候选、分数或回复。
- 达到最大新生成 token 数、生成结束标记或用户取消时停止。最大输入上下文长度和最大新生成 token 数应可配置；达到限制只停止或限制本轮计算，不删除对话显示记录。
- 推理面板应提供可展开的步骤视图：明确展示输入文本的 token 切分及边界、token 对应的演示 Embedding（可选择查看向量数值）、最后位置对上下文各 token 的 Self-Attention 权重热力图，以及 N-gram 计数／频率、候选融合分数和所选 token。
- 生成每个新 token 后，应将其追加到上下文，并更新 Tokenization 序列、位置编码及 Self-Attention 权重展示；历史对话记录不因此删除。
- 所有展示数值均注明是本地算法的教学演示数据，不是隐藏思维链或真实模型内部状态。
- 最终文本通过 tokenizer 对应的反分词规则拼接 token：英文单词之间按规则加空格，中文字符和标点按规则直接拼接；界面过程显示和最终回复必须一致。
- 角色设定和系统提示词按上述顺序纳入上下文，但 N-gram 仅能利用实际统计到的局部 token 序列；界面须说明这些提示词不保证产生语义上服从指令的回复。
- 本版本不接入真实模型，不提供知识库检索或真实模型事实问答；生成结果仅由本地共现统计 Embedding、固定参数 Self-Attention、N-gram 候选统计和采样共同产生。

### 4.5 输出

- 在独立回复区域显示最终模拟回复。
- 最终回复由推理模块逐步选中的 token 按顺序拼接组成，必须与过程面板展示的选择序列一致；用户原始输入作为提问显示在对话记录中，不重复拼入助手回复。
- 回复完成后提供复制按钮；对话历史持续显示，用户可通过“清空会话”按钮一次清除全部对话记录。
- 本版本不生成检索引用。知识库检索与来源引用功能延期至下一版本。

## 5. 推荐用户操作流程

1. 用户导入一个或多个 Markdown 语料文件。
2. 系统自动显示“预训练中...”，在后台完成 token 切分、位置标注、N-gram 计数及独立的坐标可视化数据计算，并将结果保存到浏览器。
3. 保存成功后只显示“预训练完成。”；用户点击“展示空间位置”按钮后，在弹窗中查看最新三维预训练语料视图。
4. 用户配置角色设定或系统提示词。
5. 用户输入问题并提交。
6. 页面逐步展示根据上下文查找 N-gram 候选、显示语料计数／归一化频率并选择下一个 token 的过程。
7. 页面显示由逐步选中的 token 拼接成的最终回复；用户输入和助手回复均保留在对话记录中。

## 6. 非功能需求

- 所有关键操作均提供清晰的加载、空状态和错误反馈；错误反馈不展示内部学习日志或调试细节。预训练成功提示仅为“预训练完成。”。
- 普通规模 Markdown 文件的读取与可视化不得导致页面明显卡死；较大文件需进行大小限制或给出说明。
- 对用户输入和文件内容按纯文本展示，避免将 Markdown/HTML 内容直接作为可执行 HTML 插入页面。
- 键盘可操作主要控件；按钮、输入框和三维图应有可读的标签或替代说明。
- 页面明确区分本地 N-gram 语料统计／生成模拟和真实预训练、微调及模型推理；本版本不接入模型、不包含知识库检索。

## 7. 验收标准

1. 可一次导入多个 `.md` 预训练语料文件，并能添加、替换和删除已导入文件。
2. 每次有效的预训练语料变更都会自动重新处理当前文件集合。
3. 预训练语料处理时只显示“预训练中...”，处理完成且结果保存成功后只显示“预训练完成。”，不显示中间学习步骤、日志或额外成功摘要。
4. 处理结果包含 token、类型标注、来源位置、N-gram 计数和三维坐标，并自动保存到浏览器；刷新页面后可恢复最近一次成功结果。
5. 同一序列中按实际顺序相邻的 token 发生共现时，其坐标按规则相互靠近；未发生共现的 token 不会仅因同处一个文件而被自动拉近。
6. 重复处理相同预训练语料不会无故持续改变坐标或重复累计历史更新。
7. 用户可分别编辑角色设定和系统提示词，并能在新问题的模拟处理中使用当前配置。
8. 提交问题后，推理面板会逐步展示上下文对应的 N-gram 候选、计数／归一化频率及所选 token；最终回复按反分词规则拼接且与所有选中 token 的过程记录一致。
9. 页面明确声明本地 N-gram 统计及候选分数属于算法演示，不是真实模型概率、参数更新或隐藏推理过程；没有任何真实模型或模型 API 调用。
10. 页面不提供知识库检索、基于知识库的问答或来源引用；这些功能标记为下一版本范围。
11. 对于语料中有统计记录的上下文，系统依据对应 N-gram 候选计数选取 token；无匹配时按较短上下文回退，仍无候选则按规定停止，不得改用三维距离续写。
12. 系统允许已生成 token 在同一回复中再次出现；在达到最大新生成 token 数、遇到结束标记或用户取消时停止。
13. 固定语料、上下文、采样设置和随机种子时，生成结果可重复；贪心、温度和 Top-k（如提供）行为符合需求定义。
14. 预训练初始化及每次坐标更新后，任意两个不同 token 的坐标均不重叠，且三维欧氏距离不小于配置的最小间距；发生位置冲突时，被抢占 token 会按空位优先、无空位时随机抢占并继续级联的规则搬移；二维视图中的文字标签也不会相互遮挡。坐标不影响 N-gram 生成。
15. 系统自动计算并限制三轴坐标最小值和最大值；初始范围至少容纳不同 token 数量 30 倍的、满足最小间距的可用位置。语料规模增加时自动扩容，且坐标不会因随机初始化出现不受控的大范围离散。
16. 预训练成功后结果已持久化至浏览器，界面只显示“预训练完成。”；刷新后可恢复 tokenizer 版本和 N-gram 统计。
17. 用户点击“展示空间位置”后，三维视图在弹窗中打开；用户可放大、缩小并进行 360 度旋转，且可关闭弹窗并恢复操作焦点。
18. 当前会话中的所有用户输入和系统回复按时间顺序持续显示；系统不会自动删除旧记录，用户点击一次“清空会话”即可清除全部会话记录，且不影响预训练结果和提示词配置。
19. 用户提交文本后，可在推理步骤视图中看到 tokenizer 产生的 token 序列；每个 token 的演示 Embedding 可查看，且不与 3D 显示坐标混淆。
20. Self-Attention 展示符合因果掩码：某一位置不得关注其后的 token；最后位置的注意力权重归一化后总和为 1，并在追加 token 后按新上下文更新。
21. 候选融合分数能根据 N-gram 频率和注意力输出与候选 Embedding 的相似度计算；改变三维显示坐标不会改变候选集、分数或生成结果。
