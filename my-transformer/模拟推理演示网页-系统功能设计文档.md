# 模拟推理演示网页——系统功能设计文档

## 1. 设计目标与边界

### 1.1 设计目标

本系统是一个纯浏览器端教学演示网页，展示 Tokenization、共现统计 Embedding、简化 QKV Self-Attention、N-gram 候选统计及逐 token 采样生成，并以 3D 投影近似可视化 Embedding 的语义关联。不调用真实模型、模型 API 或服务器。

### 1.2 明确不实现的内容

- 不进行完整 Transformer 前向计算、梯度训练、参数学习、参数更新或真实模型微调；Self-Attention 仅实现本设计定义的单层单头教学计算。
- 不执行知识库检索、RAG 或真实事实问答。
- 3D 坐标是 16 维共现统计 Embedding 的近似语义关系投影，并非真实模型学到的语义向量；坐标本身不参与 QKV、候选生成、候选评分或采样。
- 不将候选频率称作真实模型概率、置信度或模型思维链。

界面应在适当位置标记“本地统计与简化注意力算法演示，非真实大模型”。

## 2. 系统组成

采用单页前端应用，建议按职责拆分为以下逻辑模块；可使用原生 HTML、CSS、JavaScript ES Modules。

| 模块 | 主要职责 |
|---|---|
| 页面与状态控制 | 页面布局、模块状态、用户交互、状态提示及错误反馈 |
| 语料文件管理 | 多文件导入、校验、替换、删除及本地持久化 |
| Markdown 文本提取 | 安全地将 Markdown 转成纯文本，保留段落和句子边界 |
| Tokenizer | 按固定、可复现的规则将文本拆为 token，并提供反分词 |
| N-gram 统计器 | 计算 1-gram、2-gram、3-gram 计数及来源位置 |
| Embedding 生成器 | 基于 PPMI 共现特征和固定随机投影构造 16 维 token 向量 |
| Self-Attention 计算器 | 使用固定 Q/K/V 矩阵和因果掩码计算上下文关联权重及输出向量 |
| 三维布局计算器 | 将 16 维 Embedding 投影至 3D，并维护展示布局、共现边和防碰撞规则 |
| 3D 可视化弹窗 | 交互显示已保存的节点、边、标签及坐标 |
| 续写引擎 | 按输入上下文查找候选、评分、采样并逐 token 续写 |
| 对话与提示词管理 | 维护完整可见会话、角色设定和系统提示词 |
| 浏览器存储层 | 保存语料、统计结果、布局、设置和会话 |

3D 可视化可采用 Three.js 及其 OrbitControls；如选用该依赖，应随应用打包，避免运行时从不可信来源加载脚本。IndexedDB 用于保存较大的语料和统计数据，localStorage 可保存少量界面设置。

## 3. 页面结构与模块设计

### 3.1 语料统计（模拟预训练）

**界面元素**

- 多选 `.md` 文件导入控件。
- 已导入文件列表，支持添加、替换、删除。
- 状态提示，仅在处理时显示“预训练中...”，成功保存后显示“预训练完成。”。
- “展示空间位置”按钮；无成功保存的有效结果时禁用。
- 空语料状态及简洁的导入／存储错误提示。

**处理流程**

1. 读取文件并校验扩展名、读取结果和空内容。任何无效文件不得静默标记为导入成功。
2. 取得本次处理的文件集合快照，并生成语料版本标识（建议对文件名及内容计算稳定摘要）。
3. 将 Markdown 安全地提取为纯文本及段落／句子序列，不把文件内容作为 HTML 执行。
4. 使用固定 tokenizer 生成 token 序列及来源位置。
5. 从每条独立序列统计 N-gram、有向相邻共现及窗口共现矩阵。
6. 根据窗口共现计算 PPMI 特征，经固定投影生成 16 维演示 Embedding。
7. 将 Embedding 投影至 3D 作为近似语义关系图初始位置，再按布局规则处理共现聚集和坐标碰撞。3D 布局结果不得回写为 Embedding 或参与推理计算。
8. 将新版本全部结果原子化写入 IndexedDB。只有写入成功后，切换当前结果版本并显示“预训练完成。”。
9. 若处理或保存失败，显示简短错误提示，不显示成功状态，并保留上一个有效版本。

文件连续变化时采用“最后一次提交的语料快照有效”策略。旧任务即使较晚结束，也不得覆盖新任务结果；可通过递增任务版本号或取消旧任务实现。

### 3.2 Markdown 提取与 Tokenizer

#### Markdown 提取

- 输出仅作为纯文本进入统计流程；HTML 只使用文本节点安全渲染。
- 标题、列表等 Markdown 内容的正文应保留，语法标记不作为 token。
- 代码块、链接、图片和表格采用固定提取规则，并在帮助说明中简要说明；文本提取不得执行嵌入 HTML 或脚本。
- 保留文件、段落、句子边界，防止边界两侧 token 被错误拼接成 N-gram。

#### 固定 tokenizer 规则

本版本使用简单 tokenizer，而不是大模型 tokenizer：

- 中文汉字：每个汉字作为一个 token。
- 英文：连续英文字母构成一个 token；大小写按原文保留，统计时区分大小写。
- 数字：连续数字构成一个 token。
- 标点：每个标点作为独立 token。
- 空白和 Markdown 语法标记不作为 token。

Tokenizer 应记录规则版本；相同文本和版本必须生成相同 token 序列。反分词规则负责还原中英文空格及标点位置，最终展示必须与推理面板中的 token 序列一致。

每个 token occurrence 记录文件 ID、段落序号、句子序号和序列内 token 序号。节点按 token 表面形式聚合，来源位置保留全部 occurrence。类型（汉字、英文、数字、标点）仅供界面展示，不参与 N-gram 候选计算。

### 3.3 N-gram 建模

#### 序列边界

- 以句末标点、段落边界和文件边界将语料切分为互不重叠的序列。
- 每条序列开头加入起始标记 `BOS`，末尾加入结束标记 `EOS`；不同序列不拼接。
- 对每条序列统计 1-gram、2-gram 和 3-gram。重复序列及重复 token 按实际出现次数累计。

#### 数据结构概念

- `unigram[token] = count`
- `bigram[contextToken][nextToken] = count`
- `trigram[contextToken1, contextToken2][nextToken] = count`

实现时应使用无歧义的结构化键（例如 JSON 序列化数组），避免 token 字符串连接造成键冲突。保存必要的来源位置索引；不要求将所有 UI 视图状态重复写入统计表。

#### 重算与持久化

- 任一语料文件增删或替换时，以完整当前文件集合重算统计，不在旧计数上重复累加。
- 为结果记录 schema 版本、tokenizer 版本、语料版本和生成时间。
- 页面刷新时优先加载最近一次成功提交的完整版本；迁移失败或数据损坏时保留旧数据并提示重新导入。

### 3.4 共现统计 Embedding 与位置编码

#### 共现统计 Embedding

- 每条独立语料序列内，对每个 token 统计左右各 2 个位置内的上下文 token 共现，不包含 token 自身位置；不得跨句子、段落或文件边界。
- 令 `count(w,c)` 为窗口内有向中心—上下文共现次数，`count(w)` 为中心 token 的共现总次数，`count(c)` 为上下文 token 的共现总次数，`total` 为所有窗口共现对总数。计算 `PPMI(w,c)=max(log((count(w,c)×total)/(count(w)×count(c))),0)`，按固定词汇顺序建立 PPMI 特征向量。
- 使用由语料版本和算法版本决定的固定随机投影矩阵，将稀疏 PPMI 特征映射到 16 维并 L2 归一化，得到 `e(token)`。该 Embedding 是从共现统计派生的确定性教学表示，不是训练得到的模型参数。
- `BOS`、`EOS` 使用固定种子生成的专用向量。输入中语料未见过的 token 使用固定 `<UNK>` 向量；不临时随机生成向量。
- 保存向量算法版本、投影随机种子和词汇索引，确保同一语料快照可重现相同向量。

#### 正弦位置编码

推理时按 token 在本轮输入序列中的位置 `pos` 生成维度 `d=16` 的固定正弦位置编码：

- `PE(pos,2i)=sin(pos/10000^(2i/d))`
- `PE(pos,2i+1)=cos(pos/10000^(2i/d))`

Self-Attention 输入为 `x_pos=e(token)+PE(pos)`。位置编码不训练，也不写入或改变 token 的基础 Embedding。

### 3.5 三维 Embedding 语义关系布局

本模块展示 16 维共现统计 Embedding 的低维关系投影。投影近邻仅近似表示共现特征相似；它不是模型真实语义空间，也不得把布局调整后的坐标反馈给续写引擎。

#### 节点与边

- 每个不同 token 对应一个 3D 节点；重复 occurrence 聚合到该节点的来源列表。
- 同一独立序列内相邻 token 按实际顺序生成有向共现边，边权重为该相邻顺序出现次数。
- 共现边表示语料中的有向相邻关系；3D 点位置近似表示 16 维 Embedding 的相对关系。两者都不代表真实模型内部表示。

#### 初始范围与位置

- 设唯一 token 数为 `N`，最小间距默认 `d_min = 1`。
- 使用按语料和算法版本固定种子的 `3×16` 投影矩阵 `R` 计算初始点 `p=R·e(token)`；将整体范围缩放／平移到自动计算的有界区域。相同 Embedding 与版本必须产生相同的基础投影点。
- 系统自动计算以原点为中心的有限 3D 网格。每个轴的网格边数取 `ceil(cuberoot(30 × N))` 或更大，保证至少有 `30 × N` 个合法槽位；各轴边界由网格边数和 `d_min` 推导。若基础投影点碰撞，则将投影点映射至最近的合法槽位，并运行碰撞解决规则。
- 网格槽间距不得小于 `d_min`。语料增加且容量不足时扩展网格边界；新 token 尽量放在其 3D 投影附近的空槽。
- 对现有语料重算时，已存在 token 尽量沿用已保存坐标；语料变化时从确定性投影基准重新计算吸引结果，避免重复处理导致坐标持续漂移。

#### 共现靠近与级联搬移

- 对每次相邻共现，按当前两个节点坐标，使二者在 x、y、z 轴分别朝向对方靠近，每轴移动不超过 1；轴向距离不大于 2 时可以中点为目标，但需遵守 `d_min` 且不得越过。
- 若目标网格槽被占用，允许移动节点抢占，并递归搬移原占用节点：先搜索周围最近的空槽；当前搜索范围无空位时，在周围占用槽中按确定性伪随机顺序选择一个抢占，继续级联。
- 级联过程中维护槽占用表、visited 集合和最大搬移步数；找到空槽后回溯提交整条搬移链。找不到合法布局时扩展范围；仍失败则回滚本次布局更新。
- `d_min` 防重叠优先于吸引规则。处理完成后须验证所有节点均在边界内且任意两点距离不少于 `d_min`。
- 随机种子由语料版本及处理顺序稳定生成，使相同输入可复现相同布局。

> 网格容量与边界属于布局约束。用于 QKV 及候选评分的是原始 16 维 Embedding，而非 3D 投影坐标。

### 3.6 三维空间弹窗

- 点击“展示空间位置”打开弹窗，读取最近一次成功保存的布局版本。
- 使用 3D 散点显示 token 节点和共现边；支持拖动 360 度旋转、滚轮或按钮缩放、恢复默认视角。
- 选择节点后显示 token、类型、坐标和来源位置；标签过密时进行屏幕空间避让或隐藏部分标签，不移动数据节点来规避标签碰撞。
- 弹窗适配桌面和移动端，支持关闭按钮与 Esc；打开后管理焦点，关闭时将焦点还给触发按钮。
- 预训练更新时旧成功布局可继续查看，但不得显示未保存的半成品为最新结果。

### 3.7 角色与系统提示词

- 分别提供角色设定和系统提示词编辑区，提供清空／恢复默认操作。
- 配置保存在浏览器本地，并按固定顺序加入每轮生成上下文：系统提示词、角色设定、对话历史、当前用户输入。
- 界面说明提示词会进入 Tokenization、Embedding 与 Self-Attention 演示上下文，但局部统计模型不保证语义遵循、角色一致或指令执行。
- 修改提示词不触发语料重新统计，也不修改 N-gram 计数和已保存 Embedding。

### 3.8 对话输入、上下文与记录

- 提供多行输入框和发送按钮；Enter 发送，Shift+Enter 换行；空输入不发送。
- 用户提交后立即将用户消息追加到对话记录；回复完成后追加助手消息。所有历史按时间显示，不自动删除、隐藏或折叠丢弃。
- 对话区域可以滚动；记录建议保存至 IndexedDB，以便刷新后恢复。清空会话按钮一次清除全部对话消息及用于生成的会话上下文，不影响语料、N-gram 统计和提示词。
- 推理中的重复提交应禁用或排队；用户取消时保留用户消息并按界面约定记录已生成部分或取消状态。
- 上下文窗口只限制本轮生成算法使用的输入，不限制界面展示和存储的会话历史。

### 3.9 逐 token 续写引擎

#### 构造查询上下文

1. 按固定顺序合并系统提示词、角色设定、当前会话历史和当前用户输入。
2. 用同一 tokenizer 转换为 token。
3. 若超出最大输入上下文长度，优先保留系统提示词、角色设定、当前用户输入和最近完整对话轮次，从最早历史轮次开始省略；显示历史不删除。
4. 若 system 与 role 设定及当前输入本身超过上限，优先保留 system 与 role，并从当前输入开头截短，界面提示本轮输入受限。

#### 简化 QKV Self-Attention

- 对每个上下文 token 查找其 16 维共现统计 Embedding；未登录 token 使用固定 `<UNK>` 向量。加上正弦位置编码后组成 `X`。
- 使用按算法版本固定种子产生的 `16×16` 矩阵 `WQ`、`WK`、`WV`，计算 `Q=XWQ`、`K=XWK`、`V=XWV`。这些矩阵固定、不训练、不在线更新。
- 使用一层、一个注意力头的因果 Self-Attention。对位置 `i`，只允许关注 `j≤i` 的位置：`α(i,j)=softmax((Qi·Kj)/sqrt(16))`，`zi=Σ(j≤i)α(i,j)Vj`。下一个 token 评分使用最后位置的 `z`。
- 每次追加生成 token 后，将新 token 的 Embedding 和位置编码追加至上下文，重新计算当前上下文的注意力权重。界面默认显示最后位置的注意力权重热力图，并可展开查看 Embedding、Q/K/V 或向量计算值。
- 此处仅模拟注意力运算流程，不是完整 Transformer 层，不含训练出的权重、残差连接、LayerNorm 或多头结构。

#### 候选回退与打分

每一步根据当前生成上下文末尾查找候选：

1. 取最后两个 token 查询 trigram；若无候选，取最后一个 token 查询 bigram。
2. 若仍无候选，查询 unigram；仍无候选则本轮停止并显示“没有匹配的语料模式”。禁止回退到三维距离。
3. 候选原始计数为语料中的 N-gram 出现次数。归一化频率：

   `p(token | context) = count(context, token) / Σ count(context, candidate)`

4. 对每个候选 token `c`，计算最后位置注意力输出 `z` 与候选 16 维 Embedding `e(c)` 的余弦相似度，并融合为模拟分数：`score(c)=λ·log(p_ngram(c|context)+ε)+(1−λ)·cosine(z,e(c))`。建议默认 `λ=0.5`、`ε=1e-8`，并提供参数配置或显示当前值。
5. N-gram 归一化频率和融合分数均为本地算法演示值，不是模型真实概率、logit 或置信度；Self-Attention 不创建候选，只影响已有 N-gram 候选的融合分数。

#### 选择策略与生成循环

- 默认对融合分数执行 softmax 后按权重采样；支持贪心选取。温度 `T>0` 时使用 `softmax(score/T)`；`T=0` 时选分数最高者。
- 可选 Top-k：按融合分数选取前 k 个候选，再应用温度和采样；同分候选按 token 字符串稳定排序。
- 使用确定性伪随机数生成器；种子由语料版本、当前输入、会话轮次和采样设置生成。相同数据、设置和随机种子产生相同序列。
- 选中 token 后，将其追加到生成序列和下一步查询上下文，重复候选查找。允许同一 token 重复生成，不因已生成过而排除。
- 生成到 `EOS` 时停止，`EOS` 不作为可见文本输出。达到最大新 token 数或用户取消时停止。
- 若语料为空或统计为空，禁用生成或提示先导入语料；不得伪造候选或回复。
- 推理面板可展开显示 Tokenization 序列、Embedding 数值、Self-Attention 权重、候选 token 的 N-gram 计数／频率、余弦相似度、融合分数和选中 token；不生成隐藏思维链。所有数值均标记为教学演示数据。

## 4. 数据与状态设计

### 4.1 浏览器存储

建议使用 IndexedDB 保存：

- **CorpusFile**：文件 ID、名称、原始文本、内容摘要、更新时间。
- **ModelSnapshot**：版本 ID、文件集合版本、tokenizer/schema/算法版本、token occurrence、N-gram 计数、PPMI 窗口共现数据、16 维 Embedding、Embedding 与 3D 投影种子、QKV 矩阵版本、坐标节点、共现边、坐标边界、布局种子、提交时间。
- **Conversation**：会话 ID、按序消息、创建／更新时间。
- **Settings**：角色设定、系统提示词、采样参数、融合参数 `λ`／`ε`、上下文上限及最大新 token 数。

localStorage 仅可用于不敏感且体积小的 UI 偏好；不得只用 localStorage 保存可能较大的语料和全部统计。

### 4.2 预训练状态机

`空闲 → 预训练中 → 保存提交 → 完成`

- 仅在处理开始显示“预训练中...”。
- IndexedDB 事务提交成功后切换当前快照并显示“预训练完成。”。
- 失败时保留旧快照，不显示完成状态，显示简短错误信息。
- 对并行任务采用版本号校验，旧任务不得覆盖新任务。

### 4.3 推理状态机

`待输入 → 生成中 → 完成／无匹配／已取消`

- 生成过程逐步更新候选与已生成 token。
- `EOS`、最大新 token 数、无匹配或用户取消均结束当前轮。
- 用户一键清空会话后，消息列表和生成上下文同时归零；其它设置和 ModelSnapshot 保持不变。

## 5. 错误处理与安全

- 拒绝非 `.md` 文件；空文件和无法读取文件应有明确提示。
- 超过设定文件大小／语料规模上限时提示限制，不得造成页面无响应。
- IndexedDB 写入失败时保留上一个有效快照，提示用户存储失败；不能误显示“预训练完成。”。
- Markdown、用户输入和 token 均按纯文本安全展示，禁止直接执行其 HTML 或脚本。
- 不发起模型 API 或语料上传网络请求；如引入图形依赖，随项目本地打包。
- 空语料、无匹配上下文、候选为空、布局无可用位置等边界状态均须有确定行为，不生成伪数据。

## 6. 非功能与可访问性

- 普通规模语料统计和布局计算不得明显阻塞界面；必要时将计算放入 Web Worker，并通过单一状态文案反映处理状态，不展示过程日志。
- 3D 弹窗需要键盘可关闭、焦点管理、可读标题和缩放替代控件；移动端提供触摸旋转与缩放。
- 主操作控件需有可访问名称；颜色不作为唯一的信息编码方式。
- 对话历史、提示词和语料的本地存储范围及清除行为应有说明。

## 7. 核心验收场景

1. 导入多个 Markdown 文件后，自动 tokenizer、N-gram 和 PPMI/Embedding 统计；过程仅显示“预训练中...”，完成并持久化后仅显示“预训练完成。”。
2. 用同一文件集合重复统计，N-gram 计数不累计翻倍；页面刷新后能恢复相同 tokenizer、Embedding 算法版本和统计快照。
3. 句子、段落、文件边界不会错误地连成 N-gram 或 Embedding 共现；有向边 `A→B` 和 `B→A` 仅按各自实际方向累计。
4. 给定相同语料、提示词、输入、采样配置和种子，Tokenization、Embedding、Self-Attention 权重、候选分数和最终 token 序列可复现。
5. Self-Attention 使用 16 维输入、因果掩码只关注当前位置及以前的位置；每个位置的注意力权重和为 1，追加生成 token 后权重按新上下文更新。
6. 候选按最长可用上下文查询，按 3-gram、2-gram、1-gram 回退；候选融合分数与 N-gram 频率和注意力输出／Embedding 相似度一致；均无候选时停止并给出规定提示。
7. Top-k 按融合分数筛选；温度对融合分数应用 softmax/缩放；允许回复重复使用 token；遇到 `EOS`、最大新 token 数或取消时正确停止。
8. 改变 3D 显示布局或坐标不改变 QKV、候选集、候选分数或生成结果；相近显示位置仅用于表达共现统计 Embedding 的近似关系。
9. 对话记录在多轮后持续完整显示；上下文窗口裁剪不删除历史；一键清空只清除会话，不影响提示词和语料快照。
10. “展示空间位置”以弹窗展示已提交的 Embedding 3D 投影布局；可 360 度旋转、缩放、关闭及恢复焦点。
11. 初始坐标范围至少提供 `30 × N` 个合法槽；所有节点满足边界和最小间距；位置碰撞按确定性级联规则处理，失败可回滚。
12. 页面明确说明本产品为本地统计与简化注意力算法演示，且运行时不调用真实模型或模型 API。
